*plugin-tools.txt*  Explicit plugin composition and package management

plugin-tools.nvim requires Neovim 0.11+; Git is needed for package operations.

SETUP                                                     *plugin-tools-setup*
>
  vim.opt.rtp:prepend('/path/to/plugin-tools.nvim')
  require('plugin_tools').setup({
    specs = {
      { id = 'my-plugin', dir = '/path/to/my-plugin', main = 'my_plugin' },
    },
  })
<
Call setup during init.lua, before native plugin loading. Installation is
explicit; startup never downloads packages. Use new(options) for an independent
manager, run install():wait(), and restart before normal startup. Alternatively,
strict=false permits startup with missing directories. If startup fails after
manager creation, status, health checks and package commands remain available;
initialization errors are retained and are not automatically retried.

COMPOSITION                                         *plugin-tools-composition*

children contains nested declarations. source/dir identifies an independent
package; a child without either shares its parent's package owner. path selects
a component directory relative to that owner. All nodes have a global id.
Repeated compatible declarations merge options and share installation.

origin optionally labels a declaration's configuration module/file. explain(id)
returns declarations in merge order and option_history with key paths and
replace/clear assignments. Labels inherit through children; manifest positions
are always recorded. Conflicts identify both sources. History stores metadata,
not extra copies of option values; opts contains the final merged values.

Root nodes default to start=true; children default to start=false. main names
the module whose setup(opts) runs on activation. config(ctx) replaces setup;
config=false suppresses setup. enabled=false omits that contribution and its
subtree. There is no separate bootstrap phase. Plugins own commands, APIs and
feature events; personal mappings and adapters belong in config(ctx). Keep setup
lightweight and defer expensive internals inside the plugin.

dependencies contains IDs or {id='other', optional=true}. It guarantees declared
availability, without initialization or activation ordering. after explicitly
requires initialization of other nodes first. Optional references may be absent.

ctx provides id, dir, opts and dependency-only has(id), activate(id), use(id)
closures. use initializes the target once and returns require(main). The plugin
decides when to call it. Context functions use dot calls; managers use colon calls.

start=false does not suppress native plugin/ scripts. Expensive work must be
deferred by the plugin itself. The manager does not intercept require(), install
loading triggers, replay runtime scripts, or unload initialized modules.

COMMANDS                                                 *:PluginTools*

:PluginTools [status]          Show each plugin's state and directory.
:PluginTools profile           Show startup stages and plugin timing.
:PluginTools log               Show the latest operation's process/phase log.
:PluginTools explain {id}      Explain ownership, users, configuration and state.
:PluginTools install [ids...]  Install missing packages, honoring the lockfile.
:PluginTools update [ids...]   Update selected packages and lock revisions.
:PluginTools plan [ids...]     Preview exact update commits and required builds.
:PluginTools apply             Apply the latest session-local reviewed plan.
:PluginTools restore [ids...]  Restore selected packages to locked commits.
:PluginTools freeze [ids...]   Record selected current checkout revisions.
:PluginTools clean             Preview unreferenced owned checkouts.
:PluginTools clean --apply     Remove those checkouts and lock entries.
:PluginTools recover           Preview interrupted transaction recovery.
:PluginTools recover --apply   Apply validated rollback or committed cleanup.

The centered rounded panel adapts columns to the window and follows the current
colorscheme. j/k move between plugins, / filters, Space selects, Enter shows
compact details, o expands full configuration, ? shows help, and l toggles logs.
P opens startup profiling; t sorts by time/name. r refreshes and q/Escape closes. u/i/s/f operate on selected nodes or the cursor node;
c previews cleanup and C applies it. Closing detaches progress observers. The
panel is loaded only on demand. manager:open() also opens it.
Selection and cursor survive resize/view changes. PluginToolsReady/Active/Warning/
Error color states; PluginToolsSelected/SelectedLine show selection. Override
those groups or PluginToolsNormal/Border/Title/CursorLine in your theme.
p previews selected updates and a applies the reviewed commits. R previews
recovery. Previews resolve Git refs but execute no builds or publication.

Git operations are asynchronous. Updates stage all builds before publication;
caught errors roll back replaced checkouts. Dirty or unowned checkouts are
protected. Local dir/dev checkouts are never updated or cleaned. Restart after
changing package files. See README.md for transaction and crash recovery limits.

API                                                        *plugin-tools-api*
>
  local m = require('plugin_tools').new(options)
  m:start()
  m:activate(id)
  local module = m:use(id)
  local available = m:has(id)
  local status = m:status()
  local explanation = m:explain(id)
  local task = m:install({ids = {'my-plugin'}})
  local result, err = task:wait(300000)
<
install, update, restore, freeze, clean, plan and recover return tasks. wait pumps the event
loop; its timeout does not cancel the task. An on_complete(result, err) option
receives completion without waiting.

on_progress(event) reports package phases and committed counts. task:subscribe(fn)
returns an unsubscribe function; task:snapshot() copies current progress.
Successful results include details with before_commit/after_commit and phases.
task.report also retains structured failure information; task.events keeps the
last 500 phase/process records. manager.last_operation retains the latest task.

plan():wait() returns a report usable with update({plan=report}) in the same
manager instance. Apply pins reviewed commits and rejects changed configuration
or checkouts. Plans do not survive a restart. recover() previews by default;
recover({dry_run=false}) applies recovery. Journal records and backups survive
caught recovery failures. Recovery refuses live owners/children, changed or dirty
checkouts, mismatched ownership, unsafe paths and changed lockfiles. Interrupted
recovery claims and legacy locks need manual inspection; see README.md.

Options: specs, root, lockfile, dev={path=...,fallback=true}, url_format,
strict=true, commands=true, concurrency=4, git_timeout=120000, profile=true.

PROFILING                                                *plugin-tools-profile*

Lightweight timing is on by default; profile=false disables collection.
P or :PluginTools profile shows stages and plugins, slowest startup first.
t toggles time/name sorting. STARTUP is exclusive configuration plus attributed
native source time; INIT and SCRIPTS separate those costs. LATER is managed
activation after startup. Enter shows inclusive/exclusive timings and script
files. Shared roots are charged once, to their package.

Stages cover resolution, runtimepath mounting, initialization, emitted native
SourcePre/SourcePost spans and other work. Total is resolve time plus start()
through the beginning of VimEnter, excluding earlier init/spec construction
and any gap between new() and start(). It is not whole-process startup time.
After VimEnter, setup reports manager startup only. Source observers are removed
at VimEnter or startup failure; startup totals then remain fixed.

Some sources inside non-nested autocommands emit no source events; those and
other unmeasured startup work appear under Other startup work. No require()
wrappers are installed. Plugin-internal first-use work is not measured unless
it runs inside a managed activation. Interrupted source samples are omitted.
manager:profile() returns copied {timings, plugins}. states retain duration_ms
(inclusive activation), self_ms, startup_config_ms, scripts_ms, startup_ms,
deferred_ms and source samples where measured.
Operation options: ids, concurrency, timeout, on_complete; clean accepts dry_run
(default true) and operates on the whole manifest. Check :checkhealth plugin_tools.
